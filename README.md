# YOL — доска заявок на передачу посылок Москва → Баку

MVP. Отправитель публикует заявку, путешественник откликается, дальше они
договариваются сами в личном чате. Площадка не участвует в сделке: не возит,
не принимает оплату, не отвечает за содержимое посылок.

Дизайн-макет, с которого снята вёрстка, лежит в `_design/`.

## Стек

- Next.js 16 (App Router) + TypeScript + Tailwind 4
- PostgreSQL + Prisma 7 (драйвер-адаптер `@prisma/adapter-pg`)
- Вход — Telegram (диплинк бота), Google, Mail.ru, почта с паролем;
  сессия в подписанной httpOnly-cookie (`jose`)
- Уведомления — тот же Telegram-бот
- Двуязычность RU/AZ — `next-intl`

### Telegram-бот

**Основной вход — через диплинк бота, а не через виджет.** Официальный виджет
грузится с `telegram.org`, который в России недоступен без VPN: у части
аудитории кнопка просто не появляется. Поэтому сайт выдаёт одноразовый код и
открывает ссылку `tg://resolve?domain=<бот>&start=<код>` — её обрабатывает
установленное приложение Telegram, минуя сайты Telegram. Бот сообщает серверу,
что код подтверждён, страница опрашивает свой же API и получает сессию.
Виджет оставлен запасным вариантом для тех, у кого он грузится.

Чтобы это работало, боту нужен вебхук. Регистрируется один раз открытием
адреса в браузере — запрос к `api.telegram.org` уходит с серверов Vercel,
поэтому VPN не нужен:

```
https://ВАШ-ДОМЕН/api/telegram/setup?secret=ЗНАЧЕНИЕ_TELEGRAM_WEBHOOK_SECRET
```

Проверить состояние вебхука — тот же адрес с `&info=1` на конце.

`/setdomain` у BotFather нужен только для запасного виджета; на вход через
диплинк он не влияет.

Что завести:

1. `/newbot` у [@BotFather](https://t.me/BotFather) → токен в `TELEGRAM_BOT_TOKEN`.
2. Имя бота без `@` → в `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`.
3. `TELEGRAM_WEBHOOK_SECRET` — любая случайная строка, затем один раз открыть
   адрес `/api/telegram/setup?secret=…` (см. выше).
4. `NEXT_PUBLIC_APP_URL` — адрес сайта, подставляется в ссылки уведомлений.

Для разработки есть вход без Telegram: выставить `ALLOW_DEV_LOGIN=1`, кнопка
появится на `/login`. Вне разработки этот вход не поднимается, даже если
переменная выставлена.

Чтобы проверить чат вдвоём, войдите в обычном окне и в приватном под разными
именами.

## Способы входа

Четыре, все ведут в один профиль:

| Способ | Когда показывается |
|---|---|
| Диплинк бота Telegram | если задан `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` |
| Google | если заданы `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` |
| Mail.ru | если заданы `MAILRU_CLIENT_ID` и `MAILRU_CLIENT_SECRET` |
| Почта и пароль | всегда |
| Виджет Telegram | запасной, ниже остальных |

Аккаунты склеиваются по почте: вход через Google и через пароль с одним
адресом ведут в один профиль.

### Про безопасность склейки

Почта при регистрации паролем **не подтверждается** — почтового сервиса в
проекте нет. Поэтому кто угодно может зарегистрироваться на чужой адрес и
ждать, пока настоящий владелец войдёт через Google. Чтобы это не привело к
захвату аккаунта, при склейке пароль у неподтверждённого адреса стирается:
провайдер владение ящиком доказывает, а неподтверждённый пароль — нет.

Когда появится отправка писем, стоит добавить подтверждение адреса и
восстановление пароля, а это правило смягчить. Пароли хранятся как scrypt
с солью; после семи неудачных попыток вход в аккаунт закрывается на 15 минут.

## Что уже работает

- Лента заявок: фильтр по категориям, четыре сортировки, счётчик откликов,
  автоматическое снятие просроченных заявок
- Публикация заявки: фото, вес, габариты пресетами, диапазон дат, цена с
  подсказкой по средней, метки «срочно / хрупкое / нужен багаж»
- Отклик путешественника: создаёт личный чат и шлёт автору пуш в Telegram
- Личный чат: опрос новых сообщений раз в 5 секунд, счётчик непрочитанных,
  звуковой сигнал на входящие. В свёрнутой вкладке опрос останавливается,
  при возврате догоняет пропущенное сразу
- «Мои заявки»: свои публикации со статусами, закрытие заявки, чужие заявки,
  на которые откликнулся
- Правила сервиса, список запрещённого, кнопка «пожаловаться»
- Полная двуязычность RU/AZ, язык запоминается в профиле

## Звук новых сообщений

Сигнал синтезируется через Web Audio API — звукового файла в проекте нет.
Браузеры не дают проигрывать звук до первого действия пользователя, поэтому
аудиоконтекст «разогревается» на первом клике или нажатии клавиши.
Настройка хранится в `localStorage` и в профиле; переключатель есть в шапке
чата и в профиле, звучит только на чужие сообщения.

## Тесты

```powershell
npm run test:db    # один раз: создаёт базу yol_test и накатывает миграции
npm run test       # прогон
npm run test:watch # в режиме наблюдения
```

Vitest. Чистая логика — форматирование, пароли, сборка ссылок OAuth, разбор
схем — проверяется без базы. Всё, что касается склейки аккаунтов, ленты,
закрытия заявок и доступа к переписке, работает на отдельной локальной базе
`yol_test`: тесты чистят таблицы перед каждым случаем, поэтому рабочую базу
не трогают, а на нелокальный адрес просто откажутся запускаться.

Файлы идут по очереди, а не параллельно: база у них общая.

## Деплой: Vercel + Supabase

Supabase закрывает и базу, и хранилище фото. Порядок такой.

### 1. Проект в Supabase

Создать проект, задать пароль базы и запомнить его — второй раз он не
показывается.

### 2. Строки подключения

**Project Settings → Database → Connection string.** Нужны обе, и обе — с
хоста `*.pooler.supabase.com`:

- `DATABASE_URL` — **Transaction pooler**, порт `6543`, с `?pgbouncer=true`.
  По ней работает приложение: на serverless соединений много и короткие,
  без пула база захлебнётся.
- `DIRECT_URL` — **Session pooler**, порт `5432`. Только для миграций: пул в
  режиме транзакций не переживает DDL. `prisma.config.ts` берёт её сам.

> Вариант **Direct connection** (`db.<ref>.supabase.co`) не подходит: на
> бесплатном тарифе он доступен только по IPv6, а Vercel и большинство
> провайдеров работают по IPv4. Платный IPv4-адрес ради этого не нужен —
> Session pooler решает ту же задачу.

Применить схему:

```powershell
npm run db:deploy
```

### 3. Бакет для фото

**Storage → New bucket**, имя `listing-photos`, отметить **Public bucket**
(картинки отдаются прямой ссылкой, подписывать нечего). Ограничение на размер
файла — 5 МБ, как в коде.

Затем **Project Settings → API**: `Project URL` → `SUPABASE_URL`, а в разделе
**API Keys → Secret keys** ключ `default` (`sb_secret_…`) → `SUPABASE_SECRET_KEY`.
На старых проектах вместо него — `service_role` со вкладки Legacy, тогда класть
в `SUPABASE_SERVICE_ROLE_KEY`; код принимает оба имени.

> Секретный ключ обходит RLS. Он только серверный: не переносить его в
> переменную с префиксом `NEXT_PUBLIC_` и не отдавать в браузер.
> Публикуемый ключ (`sb_publishable_…`) приложению не нужен вообще.

Если переменные Supabase пустые, `saveImage` пишет файлы на диск — так удобно
локально. На Vercel файловая система только для чтения, поэтому там они
обязательны.

### 4. Настройки проекта на Vercel

**Framework Preset должен быть Next.js.** Если Vercel при импорте выставил
«Other», сборка пройдёт успешно, но раздаваться будет пустая папка `public`
вместо вывода Next: все пути, включая API и статику, начнут отдавать
`404 NOT_FOUND` с заголовком `x-vercel-error`. Настройки проекта не
применяются к уже собранным деплоям — после смены пресета нужна новая
сборка, а старые ссылки с хешем так и останутся нерабочими.

Output Directory оставить пустым (Default).

### 5. Переменные на Vercel

`DATABASE_URL`, `DIRECT_URL`, `SESSION_SECRET` (новый, не из локального
`.env`), `TELEGRAM_BOT_TOKEN`, `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`,
`NEXT_PUBLIC_APP_URL`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY`,
`SUPABASE_BUCKET`.

`ALLOW_DEV_LOGIN` в продакшен **не добавлять**.

### 6. Домен боту

После первого деплоя — `/setdomain` у BotFather на адрес `*.vercel.app`.
Без этого шага кнопка входа не отрисуется.
